Introduction

Routes are defined in routes/web.php at project root. The framework uses illuminate/routing from Laravel — so if you've used Laravel before, this is identical.

There are two kinds of routes: custom URI routes and WordPress conditional routes.

Basic routing

// Custom URI route
Route::get('contact', function () {
 return view('contact');
});

// WordPress conditional route
Route::any('single', function ($post, $query) {
 return view('single', ['post' => $post]);
});

Router methods

Route::get($uri, $callback);
Route::post($uri, $callback);
Route::put($uri, $callback);
Route::patch($uri, $callback);
Route::delete($uri, $callback);
Route::options($uri, $callback);

// Match any verb (recommended for WordPress routes)
Route::any($uri, $callback);

// Match specific verbs
Route::match(['GET', 'POST'], $uri, $callback);

Tip: Use Route::any() for WordPress conditional routes. The WordPress Customizer fetches pages via HTTP POST, so Route::get() alone produces a blank screen there.

View routes

Route::view('/contact', 'contact');
Route::view('/contact', 'contact', ['team' => 'Support']);

Route parameters

// Required parameter
Route::get('/projects/{id}', function ($id) {
 return 'Project ' . $id;
});

// Optional parameter
Route::get('projects/{id?}', function ($id = 0) {
 return 'One or all projects';
});

// Regex constraint
Route::get('user/{id}', function ($id) {
 return 'User ' . $id;
})->where('id', '[0-9]+');
Note: Route parameters are not available to WordPress conditional routes. Those receive the WordPress globals $post and $query instead.

$post and $query on WordPress routes

Route::any('page', function ($post, $query) {
 return view('page', ['page' => $post]);
});

Named routes

Route::get('user/profile', function () {
 //
})->name('profile');

// Generate URL from name
$url = route('profile');

// With parameters
$url = route('profile', ['id' => 1]);

Route groups

// Middleware group
Route::middleware(['auth'])->group(function () {
 Route::get('/dashboard', function () { /* ... */ });
 Route::get('/settings', function () { /* ... */ });
});

// Namespace group
Route::namespace('Admin')->group(function () {
 // Controllers in App\Http\Controllers\Admin
});

// Prefix group
Route::prefix('admin')->group(function () {
 Route::get('users', function () {
 // Matches /admin/users
 });
});

WordPress routes

WordPress routes use WordPress conditional tags as the URI. The framework maps each condition to its core is_*() function.

Home & front page

// Blog main page (is_home())
Route::any('home', function ($post, $query) {
 return view('home');
});

// Static front page (is_front_page())
Route::any('front', function ($post, $query) {
 return view('front');
});

Pages

// All pages
Route::any('page', function ($post, $query) {
 return view('page');
});

// Specific page by slug
Route::any('page', ['contact', function ($post, $query) {
 return view('contact');
}]);

// Multiple pages
Route::any('page', [['about', 'contact', 24], function ($post, $query) {
 return view('info-page');
}]);

Single posts

// All single posts
Route::any('single', function ($post, $query) {
 return view('single');
});

// Specific post by slug
Route::any('single', ['welcome-post', function ($post, $query) {
 return view('welcome');
}]);

Custom post types

// Single CPT post
Route::any('singular', ['my-cpt', function ($post, $query) {
 return view('cpt-single');
}]);

// CPT archive
Route::any('post-type-archive', ['my-cpt', function ($post, $query) {
 return view('cpt-archive');
}]);

Taxonomies

// Category archive
Route::any('category', function ($post, $query) {
 return view('category');
});

// Custom taxonomy
Route::any('tax', ['my-taxonomy', function ($post, $query) {
 return view('tax-archive');
}]);

You can add custom conditions (e.g. WooCommerce) in config/app.php: 

'conditions' => [
 // existing conditions...
 'is_shop' => 'shop',
 'is_product' => 'product',
],
