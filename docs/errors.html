Error handling

Uses illuminate/foundation's exception handler, registered in app/Exceptions/Handler.php.

Debug mode

APP_DEBUG=true   # development — full stack traces
APP_DEBUG=false  # production — generic error pages

Keep APP_DEBUG=false during WordPress installation. PHP 8.x compatibility notices from WordPress core itself can obscure real errors.

Custom handler

namespace App\Exceptions;
use Illuminate\Foundation\Exceptions\Handler as ExceptionHandler;
use Throwable;

class Handler extends ExceptionHandler
{
    protected $dontReport = [
        \Illuminate\Auth\AuthenticationException::class,
        \Illuminate\Validation\ValidationException::class,
    ];

    public function report(Throwable $e): void
    {
        // Forward to Sentry, Bugsnag, etc.
        parent::report($e);
    }
}

HTTP exceptions

abort(404);
abort(404, 'Post not found.');
abort_if($post->status !== 'publish', 403);
abort_unless(current_user_can('edit_posts'), 403);

Logging

Uses illuminate/log (Monolog). Logs are stored in storage/logs/:

use Illuminate\Support\Facades\Log;

Log::info('User registered', ['id' => $id]);
Log::warning('Slow query', ['time_ms' => $ms]);
Log::error('Payment failed', ['error' => $e->getMessage()]);
