WP-CLI

MEAT Framework is fully compatible with WP-CLI. Standard WP-CLI commands work out-of-the-box. You can also register custom WP-CLI commands within the framework.

Setup

WP-CLI must be configured to find the WordPress install in the htdocs/cms/ subdirectory. Create a wp-cli.yml at project root:

# wp-cli.yml
path: htdocs/cms
url: http://local.test

Common WP-CLI commands

# Core
wp core version
wp core update

# Users
wp user list
wp user create john john@example.com --role=editor

# Posts
wp post list --post_type=post --post_status=publish
wp post create --post_title="Hello" --post_status=publish

# Plugins
wp plugin list
wp plugin activate my-plugin

# Database
wp db export backup.sql
wp db import backup.sql
wp search-replace 'http://old.dev' 'http://new.test'

# Cache
wp cache flush
wp rewrite flush

Custom WP-CLI commands

Register custom commands from a Hookable class:

namespace App\Hooks;

use Meat\Hook\Hookable;

class WpCliCommands extends Hookable
{
    public string $hook = 'cli_init';

    public function register(): void
    {
        WP_CLI::add_command('meat sync', MeatSyncCommand::class);
    }
}

class MeatSyncCommand
{
    /**
     * Sync products from the external API.
     *
     * ## OPTIONS
     * [--dry-run]
     * : Preview changes without writing to DB.
     *
     * ## EXAMPLES
     *     wp meat sync
     *     wp meat sync --dry-run
     */
    public function __invoke(array $args, array $assoc_args): void
    {
        $dryRun = isset($assoc_args['dry-run']);
        WP_CLI::log('Starting sync...');

        // Your sync logic here
        $count = $dryRun ? 0 : $this->doSync();

        WP_CLI::success("Synced {$count} products.");
    }

    private function doSync(): int
    {
        // implementation
        return 0;
    }
}

Artisan vs WP-CLI

  • Use Artisan (php artisan) for framework tasks: scaffolding, migrations, cache, routes
  • Use WP-CLI (wp) for WordPress tasks: users, posts, plugins, database, search-replace
