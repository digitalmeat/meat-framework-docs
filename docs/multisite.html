Multisite

MEAT Framework works with WordPress Multisite (network installations). Some configuration differences apply.

Setup requirements

Configure multisite in config/wordpress.php:

define('WP_ALLOW_MULTISITE', true);
define('MULTISITE', true);
define('SUBDOMAIN_INSTALL', false); // true for subdomain, false for subdirectory
define('DOMAIN_CURRENT_SITE', env('MULTISITE_DOMAIN', 'my-project.test'));
define('PATH_CURRENT_SITE', '/');
define('SITE_ID_CURRENT_SITE', 1);
define('BLOG_ID_CURRENT_SITE', 1);
# .env
APP_URL=http://my-project.test
WP_URL=http://my-project.test/cms
MULTISITE_DOMAIN=my-project.test

Network activation

Plugins that use MEAT Framework hooks should be network-activated for multisite compatibility. Network-activated plugins run before site plugins.

Routing in multisite

Routes in routes/web.php apply network-wide. Use conditional tags to differentiate between sites:

Route::any('home', function($post, $query) {
    $blogId = get_current_blog_id();

    if ($blogId === 2) {
        return view('sites.site2.home');
    }

    return view('home');
});

Per-site database

WordPress multisite uses separate table prefixes per site (e.g. wp_2_posts, wp_3_posts). When using Eloquent to query WordPress tables, switch blog context first:

switch_to_blog(2);
$posts = Post::where('post_status', 'publish')->get();
restore_current_blog();
Note: MEAT Framework's current multisite support is tested on subdirectory installs. Subdomain installs require additional server (nginx/Apache) wildcard configuration.
