Introduction

Instead of defining all request-handling logic in route closures, you can organize it into Controller classes. Controllers live in app/Http/Controllers/ and extend the base Controller class bundled with the framework, which uses illuminate/routing under the hood.

Generating controllers

php artisan make:controller PageController

# Resource controller (index, create, store, show, edit, update, destroy)
php artisan make:controller PostController --resource

# Invokable (single-action)
php artisan make:controller ShowProfile --invokable

# Resource + model binding
php artisan make:controller PostController --resource --model=Post

Basic controllers

<?php

namespace App\Http\Controllers;

use Illuminate\Http\Request;

class PageController extends Controller
{
 public function index()
 {
 return view('home');
 }

 public function show(Request $request, int $id)
 {
 return view('page', ['id' => $id]);
 }
}

Point a route at a controller action:

// String syntax
Route::get('/', 'PageController@index');

// Array syntax (preferred — IDE-friendly)
use App\Http\Controllers\PageController;
Route::get('/', [PageController::class, 'index']);

WordPress conditional routes with a controller

When a WordPress route needs extra parameters (e.g. a specific page), use the uses key:

Route::any('page', ['about-us', 'uses' => [AboutController::class, 'index']]);

Nested controllers

// app/Http/Controllers/Admin/UsersController.php
Route::get('admin/users', 'Admin\UsersController@index');

// or with array syntax
use App\Http\Controllers\Admin\UsersController;
Route::get('admin/users', [UsersController::class, 'index']);

Single-action controllers

<?php

namespace App\Http\Controllers;

class ShowProfile extends Controller
{
 public function __invoke(int $id)
 {
 return view('profile', ['id' => $id]);
 }
}
Route::get('user/{id}', ShowProfile::class);

Controller middleware

// In routes
Route::get('profile', [UserController::class, 'show'])->middleware('wp.cap');

// In controller constructor (preferred)
class UserController extends Controller
{
 public function __construct()
 {
 $this->middleware('auth');
 $this->middleware('log')->only('index');
 $this->middleware('subscribed')->except('store');
 }
}

Resource controllers

Route::resource('posts', PostController::class);

// Only specific actions
Route::resource('posts', PostController::class)->only(['index', 'show']);

// Exclude actions
Route::resource('posts', PostController::class)->except(['create', 'edit']);

// API resource (no create/edit HTML forms)
Route::apiResource('posts', PostController::class);

Dependency injection

The framework uses the illuminate/container to auto-resolve controller dependencies. 

<?php

namespace App\Http\Controllers;

use App\Services\BookService;
use Illuminate\Http\Request;

class HomeController extends Controller
{
 // Constructor injection
 public function __construct(private BookService $books) {}

 // Method injection
 public function show(Request $request, BookService $books, int $id)
 {
 $book = $books->find($id);
 return view('book', compact('book'));
 }
}

Route caching

For production deployments, cache routes for faster registration (up to 100× speedup):

# Generate cache (run during deploy)
php artisan route:cache

# Clear cache (run after adding new routes)
php artisan route:clear

Route caching only works when all routes use controller classes — closure-based routes cannot be cached.
