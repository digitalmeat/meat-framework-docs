Authentication

MEAT Framework uses WordPress authentication as its foundation, augmented with route-level guards via illuminate/routing middleware.

WordPress functions

if (is_user_logged_in()) {
    $user = wp_get_current_user();
}

current_user_can('edit_posts');
current_user_can('manage_options');

$loginUrl  = wp_login_url(home_url('/dashboard'));
$logoutUrl = wp_logout_url(home_url('/'));

Route middleware

// Require logged-in user
Route::get('dashboard', [DashboardController::class, 'index'])->middleware('wp.can');

// Require specific capability
Route::get('admin/settings', fn() => view('settings'))->middleware('wp.cap:manage_options');

// Group
Route::middleware(['wp.can'])->group(function() {
    Route::get('profile', [ProfileController::class, 'show']);
    Route::post('profile', [ProfileController::class, 'update']);
});

User facade

use Meat\Support\Facades\User;

$user  = User::current();
$id    = User::current()->ID;
$email = User::current()->user_email;
$roles = User::current()->roles;         // array
User::current()->has_cap('edit_posts');
User::current()->has_cap('manage_options');

API authentication

The api middleware group requires edit_posts capability by default. Customize in app/Http/Kernel.php:

protected $middlewareGroups = [
    'api' => [
        'throttle:60,1',
        'wp.can:edit_posts',
        'bindings',
    ],
];
