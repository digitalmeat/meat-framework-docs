Twig templates

MEAT Framework supports Twig as an alternative template engine. Views must end in .twig.

Basic usage

{# views/pages/home.twig #}
{% extends "layouts/main.twig" %}

{% block content %}
    <h1>Hello, {{ name }}!</h1>

    {% for post in posts %}
        <article>
            <h2>{{ post.post_title }}</h2>
            {{ post.post_content | raw }}
        </article>
    {% endfor %}
{% endblock %}
// In a route or controller
return view('pages.home', ['name' => 'World', 'posts' => get_posts()]);

Layouts & blocks

{# views/layouts/main.twig #}
<!DOCTYPE html>
<html>
<head>{{ wp_head() }}</head>
<body>
    {% include "partials/header.twig" %}
    <main>{% block content %}{% endblock %}</main>
    {% include "partials/footer.twig" %}
    {{ wp_footer() }}
</body></html>

Variables & filters

{# Output escaped (default) #}
{{ title }}

{# Output raw/unescaped HTML #}
{{ content | raw }}

{# Default value #}
{{ name | default('Anonymous') }}

{# Conditional #}
{% if is_user_logged_in() %}
    <p>Welcome back!</p>
{% else %}
    <a href="{{ wp_login_url() }}">Log in</a>
{% endif %}

{# Loop with loop variable #}
{% for post in posts %}
    <p>{{ loop.index }}. {{ post.post_title }}</p>
{% endfor %}

WordPress functions in Twig

WordPress functions are available directly in Twig templates:

{{ get_bloginfo('name') }}
{{ home_url('/contact') }}
{{ get_the_post_thumbnail(post.ID, 'medium') | raw }}
{{ the_date('d/m/Y', '', '', false) }}

Extending Twig

Add custom filters and functions from a service provider:

use Illuminate\Support\Facades\App;

public function boot(): void
{
    $twig = App::make('twig');
    $twig->addFilter(new \Twig\TwigFilter('truncate', function(string $text, int $len = 100): string {
        return mb_strimwidth($text, 0, $len, '…');
    }));
}
We recommend using one template engine per project. Blade is the default and has wider ecosystem support. Twig is a great choice if your team comes from a Symfony background.
